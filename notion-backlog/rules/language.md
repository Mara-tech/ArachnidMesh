# Language

Two destinations, two languages. The split is by **where the text lands**, not by who wrote it.

**<repo-language> — anything committed to this repository.** Source code and identifiers, comments,
`*.md` documentation, commit messages, branch names, pull request titles and bodies, and these rule
files. This is the **repository language**.

**<chat-language> — anything that is a conversation.** Chat with the user, Slack messages, and Notion
pages: ticket titles, descriptions, page bodies, reports and comments. This is the **conversation
language**.

The skills speak of « the repository language » and « the conversation language » rather than naming
one, so that this file stays the only place where the choice is written down.

A single task crosses the boundary and that is normal: a Notion ticket written in <chat-language>
produces <repo-language> code and a <repo-language> pull request, then a <chat-language> report on
the Notion page.

When writing <chat-language>, quote error messages, file paths, identifiers, commands and their
output **verbatim**. Translating them makes them unsearchable and unrunnable.
